# Simple Audio Player - Agent Reference

The source under `player/` is the truth; user docs are in `player/docs/<lang>/userguide.html`; history and status are in `project_state.md` and `CHANGELOG.md`.

## 1. Run and layout

- Stack: Python 3.11, wxPython, libmpv (`player/mpv.dll` + vendored `player/mpv.py`); deps in `player/requirements.txt` (import names differ: `appGuard` -> `app_guard`, `py-yt-search` -> `py_yt`).
- Run: `cd player; python SimpleAudioPlayer.py [paths...]`. Imports are top-level, so CWD or `PYTHONPATH` must be `player/`; `mpv.py` does `os.add_dll_directory(os.getcwd())` and loads `mpv.dll` by bare name, so another CWD breaks libmpv.
- `mpv.py` is vendored: do not edit or reformat.

## 2. Control flow

- Every input is a string `action_id` given to `AppController.handle_action` (`core/controller.py`), which does `wx.CallAfter(_run_action_and_sync, handler)` then `_sync_frame_toggles`. Sources: menu, accelerators, transport buttons, global keys (`core/keyboard_handler.py`, pynput thread), SMTC buttons (`core/windows_media.py`, WinRT thread).
- `app.py` startup: `_init_guard` -> settings load -> `_BootstrapController` (shortcut tables only) -> `Localization.init` -> `MainFrame` -> `wx.CallAfter(_initialize_controller_and_startup)` builds the real `AppController`, then `check_startup` (YouTube helpers), update check, open paths or `restore_last_session`.
- `AppController.shutdown` is an ordered list of best-effort `_run_shutdown_step` calls; add teardown there.
- `ActionContext` (`core/action_context.py`), passed to every handler, `player`, `settings`, stores, `frame`, A-B selection, YouTube state (`yt_pl`, `yt_now`, `yt_retry_source`). Speech: `ctx.speak(beginner, advanced)` over `speech.speak`.
- UI: `MainFrame` (`ui/main_frame.py`) = `ui/mainwin/{menu,state,events}.py`. Settings: `ui/prefs/dialog.py` (`ui/settings_dialog.py` only re-exports it).
- `Player` (`core/player/`) = mixins over `MpvEngine` and `PlaylistState` (`playlist/state/`, mixins).

## 3. Adding an action

1. `actions.py`: constant + `Action(id, English label, Shortcut|None, secondary)` in `ACTIONS` (labels are plain strings, not `_()`; the shortcut dialog lists them). System-wide shortcuts are the separate `GLOBAL_SHORTCUT_ACTIONS`. Indexed families (`bookmark_jump_N`, `jump_percent_*`) are generated by loops at the bottom (`BOOKMARK_JUMPS`/`PERCENT_JUMPS`, wired in the controller constructor).
2. Handler `fn(ctx)` in the matching `app_actions/*.py`, imported into `core/controller.py` and added to `AppController._action_handlers`. An id missing there is silently ignored.
3. Menu: in `ui/mainwin/menu.py` use `self._menu_label(_("Text"), ACTION_ID)` (appends the live shortcut) and `self._bind_action_item(item, ACTION_ID)`.
4. If availability changes with state (file loaded, local file, marks, recording), keep the item on `self` and toggle it in `ui/mainwin/state.py`. A menu item that also has a shortcut must be listed in `reserved_ids` in `_build_shortcuts` (`state.py`) so the accelerator reuses its id; an action without a menu item gets a generated id routed by `_on_accelerator`.
5. Overrides persist in settings sections `[shortcuts]`, `[shortcuts_secondary]`, `[global_shortcuts]`, merged by `ShortcutManager` (`config/shortcuts.py`). Accelerator tables take only ctrl/shift/alt (`ui/accelerators.py`); Win combos work only as global shortcuts.
6. Strings: section 11.

## 4. Playback engine

- `MpvEngine` (`core/mpv_engine.py`) is the only libmpv owner; it turns off mpv's media keys/controls (SMTC has one owner, `WindowsMediaBridge`) and registers one `end-file` callback.
- Volume 0..1000: with normalization on, values above 100 pin mpv at 100 and scale the `@audiopreamp` gain (`volume/100`); otherwise mpv volume is set directly. `_requested_volume` is the truth. Speed 0.5..4.0.
- Filters are labelled `af add` lavfi entries (`@audionormalize`, `@audiopreamp`, `@audiomono`, `@silenceremove`); `Player._apply_active_audio_filters` reapplies them after each load.
- `Player.set_render_window` tries assigning `wid`; on failure `MpvEngine.recreate_with_window` builds a new core (32-bit-masked HWND), restores volume/speed/filters/device/stream cache, and the player reloads at the saved position/pause state. Any runtime option added must be reapplied there.
- End of file (`core/player/lifecycle.py`, runs on mpv's event thread): reason 4 (error) -> `youtube.flow.on_playback_finished` retry; then repeat-file reloads; then `end_behavior`: `advance` (for EOF the YouTube flow gets first chance, else next track, else stop), `loop` (mpv `loop-file=inf`), `none` (`keep-open`).
- A-B loop = mpv `ab-loop-a/b`, cleared by `Player._load_current` on every load; the speaker test uses a throwaway second core.

## 5. Files and playlist

- `PlaylistState` keeps list, index, shuffle order, repeat flag, marked keys and per-path meta (`title`, `source`). Identity key `_path_key` (`playlist/state/meta.py`): URLs verbatim, local paths `normcase(abspath)`.
- `Player.open_stream(url, append=True, ...)`: `append=True` adds and jumps; `append=False` replaces the playlist. A YouTube stream's path is an ephemeral resolved URL; meta `source` is the canonical watch URL. `queue_stream`, `replace_queued_stream`, `replace_current_stream`, `remove_sources` keep the playlist aligned with prefetch.
- Open modes (`file_only`, `main_folder`, `main_and_subfolders`): `app_actions/file_actions.py`, scans in `core/media_library.py`; shell paths are debounced 120 ms in `app.py`.
- Per-file resume: `_save_pos`/`_restore_pos` in `file_actions.py`, only when `audio.save_file_pos` and the file is local.
- Extension lists must match across `AUDIO_EXTENSIONS` (`config/constants.py`), `VIDEO_EXTENSIONS` (`config/file_associations.py`), `AUDIO_WILDCARD` (`ui/dialogs.py`) and the `.iss` rows (validator).

## 6. YouTube

- `yt-dlp.exe`/`deno.exe` live in the app dir (`youtube/components.py`), are never bundled (`player/youtube/RUNTIME_COMPONENTS.md`), are installed on first use (`startup.check_startup`) and updated by `update_all` (yt-dlp `--update-to <channel>@latest`; Deno from the GitHub release zip, extracted atomically). Call `add_to_path()` before spawning them.
- Search (`youtube/search.py`): `py_yt` `VideosSearch` run by `_run_search_sync` (fresh thread, fresh event loop, `httpx` client closed in `finally`; never reuse a coroutine). Import-time patches: `ComponentHandler._getShelfComponent` (guards missing lists) and `SearchCore._getRequestBody` (moves `hl`/`gl` into `context.client`; YouTube ignores them at top level). Bad `hl`/`gl` codes get HTTP 400: settings normalize them and `start_search` retries once with `en`/`US`.
- Resolver (`youtube/resolver.py`): yt-dlp via `_run_lines` (cancel-aware, 90 s timeout), args `youtube:player_client=android`, `--js-runtimes deno:<path>`; `resolve_stream` falls back JSON -> `-g` with format -> plain `-g`. HTTP 429 raises a rate-limit error. `fetch_play` returns `{item, stream}`. `flow.open_yt_link` honors `mixed_link_mode` (ask/video/playlist).
- Session dict (`youtube/state.py` `mk_ses`): `kind` in `playlist|search|feed|channel`; keys `items`, `urls`, `sel`, `queued`, `*_jobs`, `pending_next`, `prep_keys`, `cancel`, plus `audio_only`/`quality` copied at creation. The live one is `ctx.yt_pl`; change it only with `set_ses`/`clear_ses`/`cleanup_ses` (they cancel flag and futures); call `sync_removed_sources` when playlist sources are removed.
- Prefetch (`youtube/flow.py`): `_PREP_POOL` (4 workers), `_PREP_FUT`, `_PREP_DONE` cache (TTL 600 s, max 200, key `url|a=<0/1>|q=<quality>` from `_prep_key`), all under `_PREP_LOCK`. `_prefetch_range` cancels queued jobs outside the window; `_prep_play` joins a prefetch only if it started, else fetches directly.
- `_play_item` sets `cache-secs` from `youtube.cache_minutes` (0 = mpv default), disables shuffle, opens with `append=False`.
- Auto-advance (`_should_auto_advance_session`): at natural EOF only if session kind is `playlist`, repeat-file is off and `end_behavior` is `advance`. Search/feed/channel sessions never auto-advance; `NEXT_TRACK` still uses `try_next`. A stream error retries once per source (`ctx.yt_retry_source`; `_retry_failed_stream` evicts the cache key and re-resolves).
- `youtube/task_ui.run_task(parent, title, job, simple=)` runs `job(cancel, on_line, on_up)` on a worker under a modal dialog; the job must not touch wx.

## 7. Subscriptions, favorites, bookmarks, positions, recording

- Subscriptions (`subscriptions/`, RSS, no login): `feed.py` reads `feeds/videos.xml`, drops Shorts, resolves `@handle` links from page HTML with cookie `CONSENT=YES+1`. `app_actions/subscription_actions.py`: `open_latest` merges channel feeds only (50 items), playlists open via `open_yt_link`; lists show through `youtube.flow.show_videos` (kinds `feed`/`channel`).
- Favorites, bookmarks, positions, subscriptions each have a `store.py` (plus `model.py` where needed), all reading and writing through `helpers/json_store.py` (`read_json` returns `{}` on missing/corrupt files, `write_json` is atomic), and sit next to `settings.ini` (stores take `settings.config_path`).
- Shared helpers: `helpers/utils.fmt_bytes` (download sizes); `core/keyboard_handler.MODIFIER_KEYS`/`SPECIAL_KEYS` are reused by `ui/shortcut_settings.py`, which adds Home/End/Delete/Backspace that the global listener ignores.
- Recording (`recording/`): `RecEngine` capture thread, WAV/MP3 sinks, `pyaudio` imported lazily; owned by the controller, stopped at shutdown.

## 8. Persistent data

Folder `%APPDATA%\Simple Audio Player\` (`SettingsManager._resolve_config_path`). Writes go through `helpers/atomic_io.atomic_write` (temp file in the same dir, flush, fsync, validator parse, `os.replace`); never write these files any other way.

- `settings.ini` (ConfigParser). Sections: `audio`, `silence_removal`, `ui`, `youtube`, `recording`, `playback`, `shortcuts`, `shortcuts_secondary`, `global_shortcuts`. Defaults in `SettingsManager.__init__`; getters validate/clamp. `save()` writes all only if `ui.save_on_close`, else just that flag. The settings dialog saves with `snapshot_config`/`restore_config` rollback.
- `bookmarks.json`: `{"version":1,"files":{<key>:[{"id","name","path","pos","created"}]}}`.
- `favorites.json`: `{"version":1,"items":[{"id","name","kind","link","created"}]}`, `kind` in `video|playlist|combined|generic_stream`.
- `positions.json`: `{"version":1,"files":{<key>:{"path","pos","updated"}}}`.
- `subscriptions.json`: `{"version":1,"items":[{"id","kind","name","url","added"}]}`, `kind` is `channel` or `playlist`.
- `<key>` = URL verbatim or `normcase(abspath)`.

## 9. Process integration

- Single instance (`app.py` `_init_guard`): `AppGuard` handles `SimpleAudioPlayer.MainInstance` and `SimpleAudioPlayer.OpenPaths`. A second process sends `{"paths": [...]}` to the first, calls `focus_window` only if `ui.focus_on_shell_open` (read from disk; only that short-lived process holds Explorer's foreground right), and exits before any wx window. The primary hops from the guard thread with `wx.CallAfter`; early paths wait in `_pending_open_paths`.
- SMTC (`core/windows_media.py`): WinRT `MediaPlayer`, command manager disabled; buttons map to action ids; `AppController._media_timer` (1000 ms) pushes state. Init failure must leave the app running.
- App updates (`update/`): reads `info.json` from `main`, downloads `.exe` if `.sap_installed` exists in the app dir else the portable `.zip`, launches `Updater.exe <asset> <install_dir> <pid>` and exits; `updater/main.py` waits up to 300 s for the pid, then applies the zip or runs the installer.

## 10. Invariants and hazards

- Only the main thread touches wx. pynput, SMTC, mpv event thread and future callbacks marshal with `wx.CallAfter`, and check session identity/cancel flag before touching UI (`youtube/results.py` `_more_done`, `youtube/flow.py` `_queue_next_ready`).
- YouTube plays with `open_stream(append=False)` (`youtube/flow.py` `_play_item`); `append=True` mixes with earlier local playlists.
- One live YouTube session in `ctx.yt_pl`, changed only via `youtube/state.py` helpers; non-playlist sessions must not auto-advance.
- Prefetch cache/futures only under `_PREP_LOCK`; resolved stream URLs expire, so persist the canonical watch URL (`youtube/flow.py`).
- Path-key rule is duplicated in `playlist/state/meta.py` and the stores' `_key`; change them together.
- End-file order (section 4) is load-bearing and off the UI thread (`core/player/lifecycle.py`).
- mpv media keys/controls stay off (`core/mpv_engine.py`).
- Local playback must survive YouTube, network, helper and SMTC failures.
- Release must overwrite `dist/SimpleAudioPlayer/_winrt.pyd` with `winsdk/_winrt.pyd` and delete `winsdk_winrt.pyd`, else SMTC crashes (`build_test.ps1`, `release.yml`).
- `yt-dlp.exe`/`deno.exe` never go in `SimpleAudioPlayer.spec` (validator).
- Module-level `_()` runs at import. `app.py` imports `ui.main_frame` (hence `app_actions.playback_actions`) before `Localization.init`, so module-level translated strings miss the catalog; call `_()` inside functions (see `playback_actions.seek_step_labels`, `yt_dialogs.missing_msg`). Key names in `config/shortcut_utils._KEY_DISPLAY` stay English on purpose: they follow `\t` in menu labels, where wx parses them as accelerators.
- Preferences > Backup and restore (`ui/prefs/backup.py`): `export_library`/`import_library` move favorites and subscriptions as one `{"version":1,"favorites":{...},"subscriptions":{...}}` file; import validates both parts before writing either.
- File-info action (`F`) cycles on presses within 0.3 s (`ActionContext.should_reset_file_info`).

## 11. i18n

- Domain `SimpleAudioPlayer`; Arabic and Czech catalogs `player/locale/{ar,cs}/LC_MESSAGES/SimpleAudioPlayer.{po,mo}`, template `player/locale/simple_audio_player.pot`. Strings are English, wrapped in `_()`; counted strings use `gettext.ngettext(singular, plural, n)` called through the module (`Localization` swaps `gettext.ngettext` at runtime, so a name imported earlier stays untranslated), as in `subscriptions/feed.age_label`. The template is built with `--keyword=_` and `--keyword=ngettext:1,2`; Arabic has 6 plural forms, Czech 3 (`Plural-Forms` in each `.po` header).
- `python scripts/update_pot.py` (from `player/`): `xgettext` over every `.py` (skipping `dist`, `build`, venvs, `--sort-by-file`), then per `.po` `msgmerge -q -U --backup=none` and `msgfmt -c` to `.mo`; `--pot-only` makes the template alone. Needs GNU gettext on `PATH`; never rewrite `.po` with polib.
- A language is offered only if its `.mo` exists; changes need a restart.

## 12. Build and release

- Version lives in `info.json`, `player/config/constants.py` `APP_VERSION`, `player/simple_audio_player.iss` `MyAppVersion`. `python scripts/update_version.py X.Y.Z` (leading `v` stripped) edits all three, then runs the validator.
- `python scripts/validate_project_consistency.py` (from `player/`) enforces: three versions equal; extension lists equal across constants, file dialog and four Inno registry groups; each locale has `<DOMAIN>.mo`; packaging assets exist and are referenced by the spec; `.sap_installed` marker and `Updater.exe` packaged in the `.iss`; release asset name `SimpleAudioPlayer-v{version}.{ext}` produced by `release.yml`; `RUNTIME_COMPONENTS.md` exists and the spec omits `yt-dlp.exe`/`deno.exe`.
- Build order (`build_test.ps1`, `release.yml`), from `player/`: build `Updater.exe` (`PyInstaller --onefile --windowed --noupx --name Updater updater/main.py`, copy to `player/`); `PyInstaller --noconfirm SimpleAudioPlayer.spec` with `PYTHONPATH=player` (`player/SimpleAudioPlayer.spec` roots at `Path.cwd()`, onedir with `contents_directory="."`); the `_winrt.pyd` swap; `iscc player/simple_audio_player.iss` (per-user install, writes `.sap_installed`), rename to `SimpleAudioPlayer-v<ver>.exe`, zip the onedir as `.zip`. `player/Updater.exe`, `yt-dlp.exe`, `deno.exe` are git-ignored; `mpv.dll` is tracked.

## 13. Tests and conventions

- Tests: only `player/subscriptions/run_tests.py` (`cd player; python subscriptions/run_tests.py [--live]`; `--live` queries YouTube once); `player/tests/` is deleted. Convention: small standalone `run_tests.py` scripts of plain functions, no pytest, with `player/` inserted into `sys.path`.
- Style: PEP 8, snake_case; `python scripts/format_code.py <path>` runs black (not `mpv.py`) then flake8 `--max-line-length=88`.
- User strings: `_()` in Python only; spoken text via `ctx.speak`. Subprocesses: `CREATE_NO_WINDOW`, UTF-8, `helpers/subprocess_utils.stop_process`.
